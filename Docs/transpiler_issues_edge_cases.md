# Py2V Transpiler Edge Cases Issues

The following issues were identified while transpiling Python code containing string/list slicing with steps, dictionary comprehensions using `enumerate`, and `nonlocal` variable scoping.

### 1. Dropped Slice Steps
**Description:**
When slicing with a step in Python (e.g., `text[::-1]` or `text[0:10:2]`), the transpiler completely ignores the step argument and simply translates it as a standard start/stop slice (`text[..]` and `text[0..10]`). V does not natively support string slicing with a step directly via brackets, so the resulting code silently performs the wrong operation without warning the user.

**Expected Behavior:**
The transpiler should map sliced strings/lists with step parameters to a V helper function or custom logic that iteratively slices or reverses the sequence. For example, `text[::-1]` should likely be transpiled to `text.reverse()`. If translation is not supported, it must raise a warning rather than dropping the step argument.

**Generated Output:**
```v
    text := 'Hello, World!'
    reversed_text := text[..]    // missing -1 step logic
    every_other := text[0..10]   // missing 2 step logic
```

### 2. Dict Comprehension Types Inference Failure
**Description:**
When translating the dictionary comprehension `{k: v for v, k in enumerate(keys)}`, the transpiler fails to infer the correct map type. Because `k` comes from the `keys` array (which is `string`), the key should be a string, and `v` (the index) should be an integer. The transpiler instead generates `mut my_dict := map[int]int{}` and then attempts to assign `my_dict[k] = v`, causing a V compilation error since `k` is a string being used on an `int` key map.

**Expected Behavior:**
The transpiler should properly analyze the types of variables generated by `enumerate()` to generate `map[string]int{}` in this scenario.

**Output from V compiler:**
```
test_edge_cases.v:18:20: error: invalid key: expected `int`, not `string`
   16 |     for v, k in keys {
   17 |         if v > 0 {
   18 |             my_dict[k] = v
      |                    ~~~
```

### 3. Broken `nonlocal` Keyword and Scoping
**Description:**
When the transpiler translates a nested Python function that relies on the `nonlocal` keyword (e.g., `increment` mutating `count`), it hoists the nested function to the module level as `pub fn increment()`. It then simply comments out the `nonlocal count` directive as `// nonlocal count`. Because the function is now at the module level and not a closure, `count` is entirely undefined, causing a compiler error. Furthermore, its return type isn't inferred properly.

**Expected Behavior:**
Just as with closures capturing variables, the transpiler should translate `nonlocal` by correctly keeping the inner function anonymous, ensuring it is declared with a capture list `[mut count]`, or appropriately wrapping it so that mutation affects the outer scope variables in V.

**Output from V compiler:**
```
test_edge_cases.v:25:5: error: undefined ident: `count`
   23 | pub fn increment() {
   24 |     // nonlocal count
   25 |     count += 1
      |     ~~~~~
   26 |     return count
   27 | }
```
