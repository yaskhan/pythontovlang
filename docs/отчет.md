# Отчет о производительности транслятора Python -> Vlang

## Описание проблемы
Транслятор стал работать значительно медленнее. Профилирование с помощью `cProfile` показало, что основным узким местом в производительности является плагин mypy (`py2v_transpiler/core/mypy_plugin.py`), а именно метод `report_config_data` и локальные импорты.

## Причины замедления
1. **Дублирующаяся обработка типов:** В методе `report_config_data` происходил цикл по `self.checker.type_map.items()`, где каждое выражение заново обрабатывалось при каждом вызове метода, что приводило к повторной (и крайне избыточной) оценке сотен тысяч одних и тех же выражений.
2. **Дублирующийся обход файлов:** В том же методе `report_config_data` каждый `file_node` из `self._files_to_process` заново обходился через `visitor.visit(file_node)`.
3. **Медленные локальные импорты:** В часто вызываемых методах-визиторах (например, `visit`, `_mark_mutated`, `visit_assignment_stmt`) каждый раз происходил импорт модулей из `mypy.nodes`. Локальные импорты внутри "горячих" циклов значительно снижают производительность в Python.

## Решение
Для устранения проблемы были применены следующие оптимизации:

1. **Добавлено кэширование выражений (`_processed_exprs`):** Теперь `report_config_data` запоминает `id` уже обработанных выражений из `type_map` и пропускает их при повторных итерациях.
2. **Добавлено кэширование файлов (`_processed_files`):** Аналогичным образом отслеживаются уже обойденные AST-файлы, чтобы `visitor.visit(file_node)` выполнялся только один раз для каждого файла.
3. **Перенос импортов:** Затратные локальные импорты из `mypy.nodes` были вынесены в самое начало файла `py2v_transpiler/core/mypy_plugin.py`.

## Результат
В результате внесенных изменений время работы транслятора сократилось более чем в 2-3 раза. Профилировочные тесты показывают значительное снижение количества внутренних вызовов и ускорение работы самого тяжелого этапа плагина `mypy` (`report_config_data` и `visit`).
