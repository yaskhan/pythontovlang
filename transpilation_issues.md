# Отчет о трансляции файлов с помощью py2v

В данном отчете представлены результаты анализа трансляции пяти файлов из тестового набора `py2v_transpiler/tests/input/transpile/`.

## Список проанализированных файлов
1. `test_args_kwargs.py`
2. `test_context_managers.py`
3. `test_for_loop.py`
4. `test_lambda_functions.py`
5. `test_string_methods.py`

---

## Найденные ошибки и проблемы

### 1. Несоответствие имен методов строк (test_string_methods.py)
Транспилятор переносит названия методов из Python "как есть", что приводит к ошибкам компиляции в V, так как в стандартной библиотеке V они называются иначе.

- **Python:** `s.strip()`, `s.lstrip()`, `s.rstrip()`
  **V (сгенерировано):** `s.strip()` (Ошибка: должно быть `trim_space()`, `trim_left()`, `trim_right()`)
- **Python:** `s.lower()`, `s.upper()`
  **V (сгенерировано):** `s.lower()` (Ошибка: должно быть `to_lower()`, `to_upper()`)
- **Python:** `s.find()`, `s.index()`
  **V (сгенерировано):** `s.find()` (Ошибка: в V это `index()` или `index_any()`, и поведение отличается)
- **Python:** `s.format(...)`
  **V (сгенерировано):** `s.format()` (Ошибка: в V нет метода `.format()`, используется интерполяция `${}`)

### 2. Отсутствие захвата переменных в замыканиях (test_lambda_functions.py)
В V замыкания (анонимные функции) требуют явного перечисления захватываемых переменных в квадратных скобках `fn [var] (args) { ... }`.

- **Пример ошибки:**
  ```v
  // Python: multiplier = lambda n: lambda x: x * n
  multiplier := fn (n int) int { return fn (x int) int { return x * n } }
  ```
  **Проблема:** Внутренняя функция не захватывает `n`. Должно быть: `fn [n] (x int) int { ... }`.

### 3. Неправильная трансляция разворота строки (test_string_methods.py)
- **Python:** `s[::-1]` (разворот строки)
- **V (сгенерировано):** `s[..]`
- **Проблема:** В V слайс `[..]` просто копирует всю строку. Для разворота в V требуется вызов `.reverse()` (после преобразования в массив рун или байт).

### 4. Ошибки в трансляции вариативных аргументов (*args)
- **test_args_kwargs.py:** `mut print_args := fn (args ...[]int)`.
  **Проблема:** В V синтаксис `...T` уже означает, что аргументы будут собраны в массив `[]T`. Запись `...[]int` означает массив массивов, что не соответствует `*args: int` в Python.
- **test_lambda_functions.py:** `sum_all := lambda *args: sum(args)` транслируется в `sum_all := fn () Any { return sum(args) }`.
  **Проблема:** Аргумент `args` вообще потерян в сигнатуре функции.

### 5. Некорректный синтаксис filter/map (test_lambda_functions.py)
- **Сгенерированный код:** `evens := []Any(nums.filter(fn (x int) bool { return x % 2 == 0 }(it)))`
- **Проблема:** Это невалидный синтаксис V. `filter` ожидает либо выражение с `it`, либо анонимную функцию. Здесь же анонимная функция вызывается немедленно `(it)`, что возвращает `bool`, а `filter` ожидает предикат. Правильно: `nums.filter(it % 2 == 0)`.

### 6. Известные ограничения (подтверждено)
- **Порядок аргументов:** В `test_args_kwargs.v` подтверждена проблема с порядком: `fn (args ...[]int, kwargs map[string]int)`. V требует, чтобы вариативный параметр был последним.
- **Обработка исключений:** Используется `if C.try() { ... }`, что требует внешней библиотеки `vexc` и не является идиоматичным для V.

## Рекомендации
1. Добавить маппинг стандартных методов строк Python в соответствующие методы V (напр. `strip` -> `trim_space`).
2. Реализовать анализ области видимости для автоматического добавления захвата переменных (`captures`) в анонимные функции V.
3. Исправить логику трансляции слайсов с отрицательным шагом.
4. Скорректировать обработку `*args` и `**kwargs` в анонимных функциях.
