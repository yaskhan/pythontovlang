## Issue #35: Lambda list comprehension with late binding
**File:** test_lambda_functions.py
**Python code:**

```python

funcs = [lambda x, i=i: x + i for i in range(5)]

```

**Generated V code:**

```v

mut funcs := []int{cap: 5}

for i in 0..5 {

    funcs << fn (x int, i int) int { return x + i }

}

```
**Problem:**
- In Python, `i=i` captures the current value of `i` at definition time.
- The V code does not capture `i` - all lambdas will use the final value of `i`.

Описание проблемы (Issue #35) **верно лишь отчасти**. Автор इशью (issue) абсолютно прав насчет того, как работает Python, но **ошибается в анализе сгенерированного кода на языке V**. 

Давайте разберем факты: что здесь правда, а что нет.

### 1. Поведение Python: **Правда**
В Python цикл `for` не создает новую область видимости для переменной `i`. Если написать просто `lambda x: x + i`, то `i` будет искаться в момент *вызова* функции (late binding), и все лямбды вернут значение с последним `i` (то есть 4). 
Трюк `i=i` в аргументах лямбды — это классический способ форсировать захват значения в момент *создания* функции. Так что утверждение о Python абсолютно корректно.

### 2. Анализ сгенерированного кода V: **Неправда**
В описании проблемы сказано: *"The V code does not capture `i` - all lambdas will use the final value of `i`"*. Это неверно по двум причинам, вытекающим из самого синтаксиса V:

* **Перекрытие переменной (Shadowing):** В сгенерированном V-коде написано `fn (x int, i int) int`. Здесь `i` — это второй аргумент анонимной функции. Он **перекрывает** (shadows) переменную `i` из цикла. Эта функция вообще не обращается к `i` из цикла. Чтобы она заработала, вызывающий код должен будет передать оба аргумента (например, `funcs[0](10, 2)`), что полностью ломает логику исходного Python-кода.
* **Ошибка типов:** Сгенерированный код инициализирует `funcs` как массив целых чисел `[]int{cap: 5}`, а затем пытается запихнуть в него функции `fn (x int, i int) int`. Компилятор V просто выдаст ошибку типов и откажется это собирать.

### Как это работает в V на самом деле?
В отличие от старых версий Python или Go, V не позволяет "случайно" захватить переменную из внешней области видимости. Компилятор требует **явного захвата** (explicit captures) с помощью синтаксиса `[var]`. 

Более того, при явном захвате V копирует переменную **по значению** (capture by value), что автоматически решает проблему "late binding", характерную для Python.

Правильный перевод этого кода с Python на V должен выглядеть так:

```v
mut funcs := []fn (int) int{cap: 5} // Правильно объявляем массив функций

for i in 0 .. 5 {
    // Явно захватываем 'i' по значению с помощью [i]
    funcs << fn [i] (x int) int { 
        return x + i 
    }
}
```

### Итог
Автор Issue прав в том, что кодогенератор (транспилятор) выдал нерабочий V-код. Но причина не в том, что V использует "late binding" (использует финальное значение `i`), а в том, что генератор не умеет правильно создавать замыкания (closures) с захватом переменных в синтаксисе языка V.
